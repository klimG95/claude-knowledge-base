# claude-settings — базовый профиль разрешений

`settings.json.example` разворачивается в `<install-dir>/.claude/settings.json` и убирает большую часть подтверждений, которые агент собирает за сессию. Профиль намеренно узкий: он закрывает то, что действительно повторяется, и не трогает то, что выглядит безобидно, но даёт исполнение произвольного кода.

Установка — флагом инсталлятора:

```powershell
.\install.ps1 -CopySettings          # Windows
./install.sh --copy-settings         # macOS / Linux
```

Файл не перезаписывается, если уже существует; для перезаписи — `-Force` / `--force`.

## Что внутри и почему

| Блок | Что делает |
|---|---|
| `defaultMode: acceptEdits` | Правки файлов (Edit/Write) применяются без подтверждения. Обычно это **самый крупный** источник подтверждений — крупнее всех shell-команд вместе взятых. Shell-команды продолжают спрашивать. |
| Read-only командлеты PowerShell | `Get-ChildItem`, `Get-Content`, `Select-String`, `Test-Path`, `Get-Item`. Ни у одного из них нет флагов записи, поэтому расширение прав ограничено ими самими. |
| `smoke-test.ps1` в нескольких формах | Проверка целостности пакета запускается часто и из разных мест. |
| `deny: []` | Заготовка под read-only каталоги проекта — см. ниже. |

## Что нужно дописать под свой проект

**1. Read-only каталоги — в `deny`.** Если в проекте есть снимок образца, выгрузка или любой каталог, который правится только человеком, закрывай его явно. `deny` сильнее `allow`, поэтому это работает и при `acceptEdits`:

```json
"deny": [
  "Edit(reference/**)",
  "Write(reference/**)",
  "Edit(./reference/**)",
  "Write(./reference/**)"
]
```

Пиши обе формы пути — с `./` и без: правила сопоставляются со строкой, а не с нормализованным путём.

**2. Скрипты проверок — точными правилами.** По одному правилу на конкретный скрипт, без wildcard на раннер:

```json
"Bash(npm run typecheck)",
"Bash(npm run lint)",
"Bash(node scripts/check-tokens.mjs:*)"
```

**3. Свой чекер целостности** — по образцу строк `smoke-test.ps1`, все формы запуска сразу (относительный путь, `&`, `powershell -File`).

## Что сюда нельзя добавлять никогда

Это не перестраховка, а следствие того, как устроено сопоставление: **правило сравнивается со строкой команды по префиксу, без разбора флагов**. Всё, что подходит под префикс, разрешено — включая флаги, которые встроенный валидатор Claude Code отклонил бы.

| Не добавлять | Почему |
|---|---|
| `Bash(npm run:*)`, `make:*`, `cargo run:*` | Запуск любого скрипта проекта = произвольный код |
| `Bash(node:*)`, `python:*`, `npx:*`, `bunx:*` | Интерпретаторы и раннеры пакетов |
| `Bash(git log:*)`, `Bash(git diff:*)` | Флаг `--output=ФАЙЛ` пишет произвольные файлы. И это ещё и **избыточно**: read-only подкоманды git Claude Code разрешает сам, с проверкой флагов |
| `Bash(git fetch:*)`, `git pull:*` | `--upload-pack=<cmd>` и remote-URL вида `ext::` исполняют произвольную команду |
| `Bash(gh api:*)` | «Только GET» префиксным правилом не выражается — под него попадут POST и DELETE |
| `Bash(curl:*)`, `wget:*` | Умеют POST — это канал утечки |
| Правила с пайпом, редиректом, `-c key=value`, `VAR=x cmd` | Читаются как read-only, а исполняют или пишут |

Отдельно: не дублируй правилами то, что Claude Code разрешает сам — `ls`, `cat`, `head`, `tail`, `grep`, `find`, `git status`, `git log`, `git diff`, `gh pr view` и подобное. Такое правило не убирает ни одного подтверждения, а только расширяет права.

## Главное: правило — не первый инструмент

Замер на реальном проекте (36 транскриптов, 373 shell-вызова) дал результат, который меняет подход: **простыми одиночными командами были только 10 вызовов из 373**. Остальное — составные скрипты с пайпами и присваиванием переменных, которые префиксное правило не покрывает в принципе. Один и тот же чекер запускался 19 раз в 18 разных формах.

Отсюда порядок действий:

1. **Сменить инструмент, а не правило.** Read / Grep / Glob не спрашивают вообще и покрывают почти всё, ради чего пишутся `Get-ChildItem`, `Select-String`, `Get-Content` и `node -e`.
2. **Стандартизировать форму запуска.** Точное правило помогает, только если команда каждый раз одна и та же строка. Канонический вид записывается в конституцию проекта, а не изобретается заново.
3. **И только потом — правило**, узкое и точное.
