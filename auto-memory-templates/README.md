# Auto-memory templates

Стартовый набор шаблонов auto-memory для эпизодического слоя памяти Claude.

## Что такое auto-memory

Auto-memory — **эпизодический слой** памяти в трёх-слойной системе vault'а:

- **Семантический слой** — `wiki/` и `index.md` (знание о мире: факты, концепции, источники).
- **Процедурный слой** — `obsidian-aura/AGENTS.md` (правила работы агента, общие для любого пользователя).
- **Эпизодический слой** — auto-memory (контекст про конкретного пользователя и его проект: предпочтения, текущая работа, ссылочные эталоны на vault-страницы).

Auto-memory переживает рамки одного разговора и одной папки — это файлы вне vault, в платформо-специфичной директории Claude Code.

Полные правила связки слоёв — в `obsidian-aura/AGENTS.md` раздел «Память Claude».

## Где их класть

Платформо-зависимые пути. `<encoded-install-path>` — install-путь, где каждый разделитель (`:`, `\`, `/`) заменён на `-`.

- **Windows:** `%USERPROFILE%\.claude\projects\<encoded-install-path>\memory\`
  Пример: install `C:\Users\Alice\dev\my-vault` → папка `c--Users-Alice-dev-my-vault`.
- **macOS:** `~/.claude/projects/<encoded-install-path>/memory/`
- **Linux:** `~/.claude/projects/<encoded-install-path>/memory/`

Если папка не существует — создать её вручную или через bootstrap-агента.

## Как активировать

1. Скопировать нужные файлы из `auto-memory-templates/` в платформенный путь выше.
2. Убрать суффикс `.example` из имени: `user_language.md.example` → `user_language.md`.
3. Заполнить placeholder'ы в body содержательно (например, `<язык>` → `русском`).
4. Поправить `created` / `updated` в frontmatter на актуальную дату.
5. Удалить HTML-комментарии-инструкции (если есть в шаблоне).

`MEMORY.md` — индекс, в нём оставляйте только реально активированные файлы.

## Какие типы memory есть

| Тип | Что внутри | Шаблоны в этой папке |
|-----|-----------|----------------------|
| `user` | Постоянные характеристики пользователя: язык, роль, предпочтения, бэкграунд. | `user_language.md.example`, `user_role.md.example` |
| `feedback` | Правила поведения агента, выведенные из явных указаний пользователя: автономность, формат ответов, гибрид-режимы подтверждений. | `feedback_technical_autonomy.md.example`, `feedback_confirm_before_mutations.md.example` |
| `project` | Контекст конкретного проекта: путь к коду, GitHub-url, ключевые факты, указатели на vault-страницы. **Шаблона нет** — создаётся вручную для каждого проекта на bootstrap. | (создаётся на месте) |
| `reference` | Ссылочные артефакты для быстрого доступа: env, токены (без секретов!), пути к бинарникам, CLI-команды. | (создаётся на месте по мере появления) |

## Правила содержимого auto-memory

(Сокращённая выдержка из конституции vault'а.)

1. **Auto-memory ≠ vault.** Если факт фиксируется в vault как страница wiki — auto-memory держит только **указатель** на эту страницу (`[[page-name]]`), не дублирует содержание.
2. **При расхождении приоритет за vault.** Если auto-memory утверждает X, а актуальная страница wiki утверждает Y — доверять wiki, обновить auto-memory.
3. **Структура memory-файла:** YAML frontmatter (`name`, `description`, `type`, `created`, `updated`) → body с разделами **Why** (почему это здесь) и **How to apply** (когда применять). Эта структура позволяет агенту быстро понять контекст memory без чтения всего файла.
