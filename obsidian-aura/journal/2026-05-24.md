# 2026-05-24 — Интеграция принципов Карпатого в методологию vault'а

## Контекст

Пользователь скинул ссылку на [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills) — одиночный CLAUDE.md из 4 поведенческих принципов, выведенных из наблюдений Карпатого о типовых ошибках LLM в коде. Задача — проанализировать репо и подумать, как применить опыт в нашем vault-workflow. После анализа — комплексно добавить применимые правила и сделать части проекта совместимыми.

## Что в репо

CLAUDE.md описывает 4 принципа:
1. **Think Before Coding** — явные допущения, не выбирать интерпретацию молча, push-back когда уместно.
2. **Simplicity First** — минимум кода, никаких спекулятивных абстракций.
3. **Surgical Changes** — менять только то, что попросили; не «улучшать» соседние строки.
4. **Goal-Driven Execution** — императив → верифицируемые цели, петля до проверяемого успеха.

Распространяется как Claude Code plugin или как CLAUDE.md fragment. По форме напоминает наш `claude-knowledge-base`.

## Анализ применимости к vault-workflow

Маппинг на текущую конституцию ([[AGENTS]]) и runbook ([[runbook-vault-integration]]):

- **Think Before** — частично присутствует (PHASE 1 в runbook'е читает контекст), но **противоречит** [[feedback_technical_autonomy]] в части «спрашивай прежде чем делать». Решение: не добавлять как раздел; применять выборочно в ответах (выбранная интерпретация одной строкой в начале ответа).
- **Simplicity First** — **пробел в AGENTS.md.** Есть «vault не дублирует код», но нет защиты от over-structuring страниц (спекулятивные секции «TBD», новые шаблоны «на будущее», дробление сущности до её разрастания).
- **Surgical Changes** — **пробел в AGENTS.md.** Есть «не теряй информацию», но нет правила «не правь соседнее при содержательной правке».
- **Goal-Driven Execution** — частично в трёх фазах runbook'а. PHASE 3 — императив без verify-критериев; verify живёт только в триггере «ревизия». Решение: расширить PHASE 3 явным блоком Verify.

## Решение

Оформлено как [[adr-001-surgical-minimal-vault-updates]] (первый ADR в vault'е). Status: accepted, выполнено в той же сессии (6 файлов, существенно меньше порога 30 из AGENTS.md «Атомарность»).

Выбрана опция «точечная интеграция двух принципов» из четырёх рассмотренных. Альтернативы (полная интеграция, отдельный runbook без правки AGENTS.md, status quo) отклонены по аргументам в ADR.

## Заметки на сессию оптимизации

«Потенциальные дыры» в валидации (из [[auragrid-trading-settings]] раздел «Сводка валидаций»):
- pts-поля (first_step, trail_size, etc.) принимают отрицательные значения на уровне модели — защита только UI `min=0`. Прямой edit yaml обходит.
- `lot_size` — то же (UI `min=0.01`, схема — любое).
- `profit_fixing_direction` / `auto_calculated_profit` — могут быть отрицательными, валидация только на `!= 0`. Отрицательное значение сделает условие активации трейлинга всегда истинным → бессмысленный спам arm на любом тике.
- `max_scalp_loss` — может быть положительным, тогда условие `floating_pl <= max_scalp_loss` ловится всегда → принудительный переход в CG на первом же тике.

Это кандидаты на фикс в pydantic-моделях при сессии оптимизации, если решим закрывать дыры.
