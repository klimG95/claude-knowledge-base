# 2026-05-30 — Стратегия максимального ускорения AuraGrid

## Контекст

Пользователь: «Софт живой и рабочий, но на ультраволатильном рынке не хватает быстродействия — зависания, лаги. Подготовить стратегию максимального ускорения с сохранением полной работоспособности и функциональности».

PHASE 1 открыл: [[runbook-vault-integration]], [[index]], [[auragrid]], [[auragrid-trading-core]].

## Метод

Параллельный аудит 4 слоёв (Explore-агенты), затем верификация двух ключевых фактов по первоисточнику:
1. Hot path торгового ядра (`on_tick`, persistence, risk).
2. MT5-интеграция + IPC (threading/async модель).
3. Аналитика + логирование + log-shipping.
4. Tauri (Rust) + React UI.

Верификация в коде ([main.py:431-512](python/bot/main.py#L431-L512)): подтверждено, что `poll_loop` и IPC-сервер на одном event loop, `symbol_info_tick`/`on_tick` синхронны, в конце итерации `sleep(50мс)`.

## Ключевые выводы (диагноз)

Два независимых фронта:

- **Фронт 1 — бот отстаёт от рынка.** `POLL_INTERVAL_SEC = 0.05` + `await asyncio.sleep` в конце ([main.py:510](python/bot/main.py#L510)) → потолок ~20 тиков/сек. На XAUUSD в импульсе 50–400/сек копятся в буфере MT5 → работа по устаревшей цене. Плюс нет дедупликации тиков.
- **Фронт 2 — окно «замерзает».** Торговый цикл и IPC на одном event loop; блокировки в `on_tick` морозят отдачу в UI: 2 синхр. SQLite-записи/тик ([persistence.py:108](python/bot/state/persistence.py#L108)), `positions_get`×2/тик ([scanner.py:89](python/bot/mt5/scanner.py#L89)), `account_info`/тик, executor `sleep 0.2с×3` при NO_PRICES ([executor.py:94](python/bot/mt5/executor.py#L94)), `flush()` логов на строку ([logging.py:151](python/bot/utils/logging.py#L151)). UI-сторона: Rust-мост без батчинга ([ipc.rs:279](desktop/src-tauri/src/ipc.rs#L279)), React-каскад перерисовок, рост массивов без лимита.
- **Не виновата** аналитика — отдельный OS-процесс (см. [[auragrid-analytics-module]]); log_shipper/telemetry/heartbeat — редкие daemon-потоки.

## Вторая часть 2026-05-30 — углубление плана («продумай полностью»)

Пользователь: «продумай план полностью, чтобы предусмотреть всё». Спустился на уровень кода: прочитал [main.py:520-748](python/bot/main.py#L520-L748) (как `run()` склеивает poll_loop+IPC на одном loop), [connection.py](python/bot/mt5/connection.py) (MT5 process-global, RLock только в ensure_connected), [engine.py](python/bot/core/engine.py) (точный on_tick), [persistence.py](python/bot/state/persistence.py) (одно соединение+RLock, общее с 3 потоками), + Explore по scanner/IPC-handlers/тестам.

Ключевой вывод: расцепление потоков неизбежно вводит разделяемое состояние (снапшот-цикл читает `engine.buy/sell` напрямую, emit без `call_soon_threadsafe`). Поэтому план переработан: **безопасное ядро (Я0-2, один поток) отделено от рискованной условной эскалации (Я3, потоки)**. Прежний Я2 «разнести потоки + write-behind» расщеплён: Я2 теперь однопоточная разблокировка (write-behind + async-логи + один positions_get + кеш account_info + тюнинг ретраев), Я3 — расцепление потоков с 4 механизмами синхронизации (publish-snapshot, command-queue, MT5-lock, call_soon_threadsafe), gated на замеры.

Добавлено в [[auragrid-performance-strategy]]: реестр рисков (7 строк), краевые случаи дедупа, AuraImpulse-зеркалирование, MT5-терминал как общий bottleneck для N ботов, backward-compat (схема не меняется → без миграций), валидация на живом рынке, оценка объёма. Перф-тестов в репо нет — Я0 добавляет первый на `FakeMT5Client`.

Реализация по-прежнему не начата — ждёт «начинай».

## Четвёртая часть 2026-05-30 — реализация Ярусов 0–2 («приступай»)

Пользователь: «приступай». Ветка `perf/acceleration-tiers` от checkpoint `461904b`. Baseline pytest 1306 подтверждён зелёным до правок. Реализованы безопасные ярусы 0–2 (по одному коммиту/подъярусу, тесты после каждого):

- **Ярус 0** `10887d4` — `bot/utils/perfmetrics.py::LatencyTracker` (кольцевой, p50/p99/max), `StateStore.write_count`, расширенный `poll_heartbeat` (`on_tick_p50/p99/max_ms`, `ticks_skipped`, `persist_writes`); `tests/test_perf_metrics.py`.
- **Ярус 1** `658bdbe` — снят потолок ~20 тиков/сек (после реального тика `sleep_for=0`, не фикс. 50мс), дедуп тиков по `(time_msc,bid,ask)` со страховкой `forced_full_tick_sec=0.25`; `POLL_INTERVAL_SEC` 0.05→0.005 (теперь idle-опрос). Тело `poll_loop` переписано на единый `sleep_for` (heartbeat считается каждую итерацию). `tests/test_perf_dedup.py`.
- **Ярус 2a** `59503b1` — write-on-change персистентность (`ChannelState.persistent_snapshot`, `Engine._persist_channels_if_changed`) + `StateStore.save_channel_states` (батч одной транзакцией). Выбран write-on-change вместо timer-based — строго безопаснее (нет окна потери `last_lot_raw`). AuraImpulse уже на `_dirty`. `tests/test_perf_write_on_change.py`.
- **Ярус 2b** `aef0967` — `scanner.scan_all`/`sync_both` (один `positions_get` на оба канала) + кеш `account_info` (TTL 1с, `_make_snapshot(wiring, acc)`). `tests/test_perf_scan_all.py`.
- **Ярус 2c** `07c6f0a` — async лог-pump (`_LogPump`, фоновый писатель, off-thread write+flush) + `flush_logging`/`shutdown_logging` (барьер тестам + слив на shutdown в `run()`). Попутно фикс `_StdoutHandler` UnicodeEncodeError на cp1252. **Тюнинг ретраев executor осознанно отложён** (риск надёжности закрытия ордеров в NO_PRICES; место — Ярус 3 off-thread).

**Итог:** полный pytest **1325 passed** / 1 skipped / 16 xfailed / 2 xpassed / 0 failed (496с, из `python/`). Семантика торговли не менялась нигде. Ветка запушена + PR. Ярус 3 (расцепление потоков) — условный, ждёт замеров на живом рынке; Ярус 4 (UI) — не начат.
