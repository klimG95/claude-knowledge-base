# 2026-05-26 — Аудит Analytics модуля: формула + buffers + UI mapping

## Контекст

Пользователь сообщил: «после последних фиксов у ПО впервые заработал модуль аналитики». Запрос — проверить корректность параметров через внешние независимые источники истины. После первой попытки ручной сверки (ATR через TradingView и MT5 на XAUUSD.N — три расхождения по ATR на трёх TF) пользователь сменил подход на полный аудит кода.

PHASE 1 открыл: [[runbook-vault-integration]], [[auragrid]] MOC, [[auragrid-analytics-module]] (текущее заявленное состояние — все unblock-приоритеты закрыты 2026-05-22), [[auragrid-trading-settings]], последние journal 2026-05-25 (5 блоков — TRAIL_REWORK, MSI uninstall, AuraImpulse концепция/реализация/аудит).

## Метод

Параллельно три Agent'а (general-purpose) по направлениям:
1. **Indicators** — формулы ATR/ADX/ER/BBW/Hurst/Parkinson/GK/RV для всех TF + percentile.
2. **Sessions/Spread/Regime** — корни аномалии `Vol vs hour-baseline = 11573×`, формулы spread, что значит режим CHAOS.
3. **Buffers/Pipeline** — статус M15 buffer (после fix'а 2026-05-22), UI-маппинг «ATR/PD M15» (прочерк в виджете).

Каждый агент прочитал ~12-15 файлов под своим направлением, нашёл конкретные `path:line` для каждого finding'а.

## Что найдено: 4 системных бага

### P0 — Stale buffers (M15/H1/D1 не обновляются после старта)

`python/bot/analytics/manager.py:653-697` — `_bar_close_loop` polls **только primary TF (M5)**. Буферы M15/H1/D1 заполняются один раз через `_backfill()` при старте и больше **никогда не освежаются**. Чем дольше работает Analytics, тем сильнее эти данные «застаивают». Влияет на ATR H1/D1, ADX H1, BBW H1, Parkinson D1, GK D1, Realized D1, intraday_vol_profile.

### P0 — Backfill включает формирующийся бар

`python/bot/analytics/fetcher.py:92`:
```python
rates = mt5.copy_rates_from_pos(symbol, native_tf, 0, bars_needed)
```
Стартовая позиция `0` = текущий незакрытый бар. Должно быть `1` (как в `detect_bar_close`, fetcher.py:230, с явным комментарием «1 = последний закрытый»). Wilder seed ATR отравлен этим частичным баром; на primary эффект «вымывается» ≈5 часов; на H1/M15/D1 (вкупе с Багом #1) — никогда.

**Эти два бага вместе** объясняют наблюдаемые расхождения ATR Analytics vs MT5 на XAUUSD.N: D1 +4.24%, H1 +48.67% (катастрофа), M5 +13.37%.

### P0 — `session_vol_ratio` структурно неверная формула

`python/bot/analytics/volatility.py:94`: `safe_div(atr_h1_current, baseline, default=0.0)`. Размерностное несоответствие — `atr_h1_current` в цене (~$15.12), `baseline` это безразмерный |log-return| (~0.0013). Делить одно на другое — мусор. Сверка: 15.12 / 0.0013 ≈ 11630, что почти точно совпадает с наблюдаемыми **11573.39×ANOMALY** в виджете Sessions. Не «деление на ноль», а архитектурная ошибка.

**Правильно:** либо привести ATR к log-return-эквиваленту (`atr_h1 / close`), либо считать `realized_vol_h1` против profile из той же метрики.

### P0 — Spread block: три «лжи» в одном виджете

`python/bot/analytics/snapshot_builder.py:399, 406`:
- **«Median 24h»** на самом деле = `sum(history) / len(history)` (mean, не median); окно = `[-7200:]` при 1Hz sampling = **~2 часа**, не 24h.
- **«Swap today»** = хардкод `0.0`, никогда не считается (`total_swap_of_positions` объявлена в `spread.py:117-124` но не вызывается в `build_spread_block`).
- **«Ticks/sec»** = polling rate (10.5 ≈ tick_loop 10Hz + snapshot_loop 1Hz), не реальный тик-поток. Нет дедупликации по `tick.time_msc` в `spread.py:54-61`.

### P1 — «ATR/PD M15 = —» это by-design (не баг)

UI поле = `volatility.atr_to_pd_ratio_m15` (`desktop/src/pages/Analytics/widgets.tsx:190`), не сам ATR. Формула в `volatility.py:33-45`: ratio `atr_m15_price / (PriceDistance_pts × point)`. Требует зарегистрированный `StrategyContext` (`snapshot_builder.py:321,329`). Если стратегия не RUNNING — `ctx is None` → ratio = None → UI рисует «—». Это by-design (Wave A.6), но **диагностически невидимо**: `atr_to_pd_ratio_h1` и `atr_to_cg_pd_ratio_h1` тоже None по той же причине, но UI их вообще не показывает.

### P1 — Regime hysteresis работает на snapshot-ticks, а не bar-closes

`snapshot_builder.py:363` — `_regime_stabilizer.push(raw)` на каждом snapshot-tick (~1 Hz). Конфиг `hysteresis_bars_per_tf=3` подразумевает «3 бара», по факту это **3 секунды**. Эффективно гистерезис отключён.

### Что НЕ баг

- **CHAOS режим** — корректный fallback по `regime.py:93` при `adx_h1=21.2` (выше границы тренда 20) и `er_primary ≤ 0.4` (mixed signals).
- **Sessions Active = NY** — формула корректна (UTC-окна 13-22), `current_sessions()` работает правильно.
- **Spread Current 24 pt** + Z=0.67 — сами по себе корректны, только база сравнения сломана.
- **Календарь CSV fallback** — ожидаемо (фикс 2026-05-22).
