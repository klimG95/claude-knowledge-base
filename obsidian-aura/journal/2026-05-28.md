# 2026-05-28 — Релизный коммит: AuraImpulse v1.0 + MSI uninstall

## Контекст

Пользователь: «Последняя версия ПО была удачной, установлена и проверена. Нужен коммит и пуш». Это сигнал успешного приёмочного теста MSI-сборки, содержащей обе фичи, разработанные в сессиях 2026-05-25:

- **AuraImpulse v1.0** (4-я сессия 2026-05-25) — single-shot breakout как отдельный preset-type.
- **MSI uninstall с галочкой** (2-я сессия 2026-05-25) — in-app кнопка удаления с опциональной очисткой `%APPDATA%\GridScalp\`.

Промежуточный коммит между ними (TZ_ANALYTICS_INTEGRITY v1.0 от 2026-05-26) уже был в `main` (`fb67723`); MSI-сборка пользователя содержала всё накопленное.

PHASE 1 открыл: [[runbook-vault-integration]], [[auragrid]] MOC, [[runbook-vault-integration]], последние journal `2026-05-25.md` (5 блоков) и `2026-05-26.md`.

## Что сделано

1. Проверил состояние рабочего дерева в `auragrid/`: 15 modified + 14 untracked файлов, ничего стороннего, всё относится к двум обозначенным фичам.
2. Проверил `git log`: последний коммит `fb67723` (analytics integrity), всё остальное между ним и текущим состоянием — это две описанные фичи.
3. Оценил возможность разделить на два коммита по фичам — `desktop/src-tauri/src/lib.rs` смешивает обе фичи (mod uninstall + два impulse-handler'а + одна invoke_handler секция). Hunk-level split возможен через `git add -p`, но non-interactive из bash болезненный. Принято решение делать **один релизный коммит** — это атомарная единица доставки (user проверил их совокупно установкой MSI).
4. Стейджинг 29 файлов и коммит `2c13f5b` с подробным телом по обеим фичам (TZ-ссылки + ADR-003 + acceptance metrics).
5. `git push origin main` — `fb67723..2c13f5b main -> main` без конфликтов.

# Вторая часть сессии — AuraImpulse cooldown UX + auto-cancel pendings on stop

## Контекст

Пользователь после установки MSI: «Все работает хорошо, но выявлена проблема — после срабатывания сделки, когда включается таймер перерыва до следующей сделки, его никак не сбросить. Ни перезапусками стратегии, ни сменой настроек его не отключить. Нужно сделать так, чтобы после срабатывания появлялась кнопка (как при стоплосе на основной стратегии) и бота можно было снять с паузы вручную. Также необходимо сделать так чтобы при остановке стратегии автоматически закрывались стоящие лоты.»

PHASE 1 открыл: [[runbook-vault-integration]], [[index]], [[auragrid]] MOC, [[auragrid-impulse-strategy]], journal 2026-05-26 + 2026-05-28 (первая часть).

## Диагностика

- **Cooldown «висит навсегда» — два корня:**
  1. UI парсит `Snapshot` как AuraGrid-shape (`buy`/`sell`/`global_pl`). Bot для импульса шлёт другой shape — `engine.snapshot()` с `cooldown_seconds_remaining`. Поле падало в `Snapshot` объект но TypeScript-тип его не объявлял → ни алерта, ни таймера в UI.
  2. `ImpulseEngine` имел `reset_stopped()` (для halt после `min_account_balance`), но **не** `reset_cooldown()`. Перезапуск тоже не помогал — `cooldown_until_ts` в SQLite, переживает рестарт; `start()` его не трогает.
- **Pending'и при stop — пропуск в `stop()`:** `python/bot/core/impulse.py:187-194` — сохраняли state и переводили `running=False`, но `_remove_pending` для buy/sell не вызывался. В MT5 pending'и оставались живыми и могли сработать без бота.

## Решения (Surgical по ADR-001)

**Python (`bot/core/impulse.py`, `bot/ipc/protocol.py`, `bot/ipc/handlers.py`):**
- Новый метод `ImpulseEngine.reset_cooldown()` симметрично `reset_stopped`: обнуляет `state.cooldown_until_ts`, `_dirty=True`, save, лог `impulse_cooldown_reset_by_user`. Возвращает `True` если cooldown был активен, иначе `False`.
- `ImpulseEngine.stop()` — перед `running=False` цикл по обоим Direction'ам: если `_pending_ticket_field(d) != 0` → `_remove_pending` + обнулить cache. Лог `pendings_removed=N`. Открытую позицию не трогаем (её SL уже в MT5, как и в AuraGrid).
- `protocol.py::KNOWN_METHODS`: добавлен `"reset_cooldown"` (с комментарием — для AuraGrid no-op).
- `handlers.py::handle_reset_cooldown`: `isinstance(engine, ImpulseEngine)` → `engine.reset_cooldown()`; для AuraGrid — просто `OkResult` (нет cooldown).

**Rust (`desktop/src-tauri/src/lib.rs`):**
- Новый `strategy_reset_cooldown` Tauri command (рядом с `strategy_reset_max_loss`), `call_ipc("reset_cooldown", {})`. Зарегистрирован в `invoke_handler!`.

**UI (`desktop/src/store/strategies.ts`, `pages/Main/StrategyPanel.tsx`):**
- `Snapshot.cooldown_seconds_remaining?: number` — optional, для AuraGrid отсутствует, в TypeScript-типе под snapshot это просто `undefined → 0`.
- В `StrategyPanel.tsx`: новый стейт `cooldownBusy`, derived `cooldownRemaining` + `isImpulse` + `cooldownActive`, обработчик `handleResetCooldown` (вызывает `strategy_reset_cooldown`). Жёлтый Alert «Бот ждёт окончания паузы» с обратным отсчётом и кнопкой «Снять с паузы», рендерится только при `cooldownActive && !maxLossHit` (не перекрывается с red-Alert MaxLoss). В confirm-модалке Stop добавлено пояснение для импульса: «Стоящие отложенные ордера будут сняты автоматически».
