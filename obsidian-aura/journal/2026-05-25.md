# 2026-05-25 — TZ TRAIL_REWORK v1.0: переработка логики трейлинга (атомарный PR)

## Контекст

Пользователь поручил последовательно реализовать ТЗ `auragrid/docs/tz/TZ_TRAIL_REWORK_v1.0.md` — переработку четырёх трейлингов (scalp pending, CG pending, scalp profit-SL, CG profit-SL) вокруг двух интуитивных параметров «удалённость» и «частота обновления». Ломающее изменение: удаление полей `pending_order_offset` (scalp + CG), новая формула трейлинга, bump `config_version` 1 → 2.

PHASE 1 открыл: [[auragrid]] MOC, [[auragrid-trading-settings]], [[auragrid-trading-core]], `auragrid/AGENTS.md` (раздел МQL5-ТЗ v2.0), [[runbook-vault-integration]], [[adr-001-surgical-minimal-vault-updates]], последний journal `2026-05-24.md`. Прочитал ТЗ целиком — 56 файлов под правкой, blast radius максимальный.

## Что сделано (10 шагов реализации)

1. **Pydantic-модели** (`python/bot/models/config.py`):
   - Удалены `ScalpingConfig.pending_order_offset`, `ConservativeGridConfig.pending_order_offset`.
   - Добавлены field-валидаторы `trail_update_distance > 0` и `trail_update_distance_profit > 0` (защита от спама modify, замена старого инварианта).
   - Снят инвариант `trail_update_distance_profit > trail_size_profit`.
   - Бамп `config_version` 1 → 2; новый `IncompatibleConfigVersionError` + понятное сообщение в `_assert_compatible_version`.
2. **Python ядро** (`scalping.py`, `conservative_grid.py`, `profit_trailing.py`):
   - `should_place_grid_order`: `threshold = current_step + trail_size` (вместо `+ pending_order_offset`).
   - `trail_pending_order` (scalp + CG): порог пересчёта = `trail_size + trail_update_distance` (универсальная формула).
   - `profit_trailing.manage` Б-ветка: то же для SL.
   - В логи `scalp_trail_moved`, `cg_trail_moved`, `profit_trail_updated` добавлены поля `trail_size`, `trail_update_distance`, `threshold`, `dist_pts`.
3. **YAML-пресеты** (4 серверных + 2 desktop + 2 e2e + 6 parity-фикстур): bump `config_version: 2`, удалены `pending_order_offset`, согласованы trail-параметры под новую семантику.
4. **Аналитика**:
   - `StrategyContext.pending_order_offset_pts` → `trail_size_pts` (manager.py, ipc_handlers.py).
   - `distance_to_next_fill(pending_offset_pts=...)` → `trail_size_pts=...` (position.py, snapshot_builder.py).
   - `useAnalyticsStrategyContext.ts` обновлён.
   - `_fsm_ops.py` симулятора: `_should_place_grid_order` использует `trail_size`; `_trail_pending` и `_manage_profit_trailing` Б-ветка — новая формула.
   - `tools/set_to_yaml.py`: `PendingOrderOffset` / `CG_PendingOrderOffset` ушли в `IGNORED_KEYS` (импорт старых MQL5 .set теряет эти поля с warn — намеренно).
   - `generate_presets.py`: `PendingOrderOffset` / `CG_PendingOrderOffset` убраны из .set-шаблона.
5. **Тесты**: conftest (главный + integration/), test_config (новый тест на отвержение pending_order_offset + config_version=1), test_scalping_part_a/b/c, test_protection, test_engine_on_tick, test_engine_process_channel, test_ipc_wizard_handlers, test_data_dir_persistence, test_simulator_fsm, test_ipc_compute_deployment, test_position — все обновлены.
6. **Acceptance-тест** `python/tests/test_trail_rework_acceptance.py` — 6 тестов закрепляют численный пример из ТЗ §2.5 (SELL pending этап А + Б, SELL profit активация + 2 подтяжки, BUY зеркально). Float-граничные точки (dist=22.0 точно) обойдены — комментарий в тесте про float-precision.
7. **TypeScript UI** (`Step3Editor.tsx`): удалены поля `pending_order_offset` (scalp + CG), переименованы labels («Удалённость ордера / Частота обновления»), снят клиентский pre-flight инварианта `trail_update_distance_profit > trail_size_profit`, добавлены проверки `> 0` на trail_update*.
8. **Rust** (`strategies.rs`): `config_version: Value::Number(2.into())` при создании нового yaml стратегии.
9. **Документация**: `docs/tz/TZ_PYTHON_MIGRATION.md` секция 3.5 (новый yaml), `docs/qa/scenarios/buy_lifecycle.md` + `sell_lifecycle.md` — `PendingOrderOffset` → `TrailSize` в формуле добора с комментарием.
10. **Верификация**: `pytest tests/ tests/integration/ tests/preset_eval/ tests/analytics/` — 696/696 passed (1 pre-existing fail починен попутно — `test_invalid_preset_rejected` обновлён под новый валидатор). `npm run build` — без ошибок. `cargo check` — без ошибок (8 warnings dead-code pre-existing).
