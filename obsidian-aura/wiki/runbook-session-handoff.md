# Runbook: передача работы в новый чат (session handoff)

Процедура для случая, когда контекст текущего чата с Claude исчерпан и работа продолжается в новом чате. Парный к [[runbook-session-start]]: тот описывает что **агент** делает автоматически при старте, этот — что **пользователь** делает, чтобы передать работу.

## Prerequisites

- Текущая сессия Claude приближается к лимиту контекста или завершается по другим причинам.
- Все изменения текущей сессии зафиксированы в `CHANGELOG.md` и `journal/YYYY-MM-DD.md` (стандартный финальный sweep по триггеру «закрой сессию» из `AGENTS.md` раздел «Автономность и триггеры»).
- Создан handoff-файл `journal/YYYY-MM-DD-handoff.md` с компактным обзором состояния (что было, что есть, что открыто).
- Корневой symlink `<root>/AGENTS.md` работает (создаётся install-скриптом пакета).
- Auto-memory актуальна — указатели в vault не устарели.

## Procedure

**Шаг 1.** Закрой текущий чат с Claude.

**Шаг 2.** Открой новый чат в Claude Code в корне рабочей папки (или подпапке). При запуске автоматически подгрузятся:
- `<root>/AGENTS.md` (через symlink) — полная конституция vault.
- Auto-memory из служебной директории профиля Claude Code — указатели, правила, контекст пользователя.
- (Если запуск из подпапки проекта с собственным AGENTS.md) — project-specific reading map и порядок обязательного чтения.

**Шаг 3.** Первым сообщением вставь handoff-промпт ниже. Подставь дату последнего handoff-файла перед использованием.

```
Ты — мой агент в Obsidian-vault. Конституция и auto-memory уже подгружены автоматически (через корневой symlink AGENTS.md и стандартный механизм Claude Code).

Перед первым содержательным ответом выполни процедуру из runbook-session-start. Минимум:
1. obsidian-aura/journal/<последний-handoff-файл>.md — компактный обзор: что было в предыдущих сессиях, что есть, что открыто.
2. obsidian-aura/wiki/methodology-overview.md — карта системы (структура, три слоя памяти, главные процессы, ADR-история, точки входа).
3. obsidian-aura/wiki/runbook-session-start.md — формализованный чеклист твоего поведения на старте.

Если задача касается конкретного проекта — дополнительно последние одну-две записи journal/ и MOC проекта в wiki/ (по правилу «Работа над конкретным проектом» в AGENTS.md).

Действуй автономно по разделу «Автономность и триггеры» AGENTS.md. Стандартные команды («обработай», «сохрани», «закрой сессию», «зафиксируй решение», «у нас инцидент», «проверь всё», «измени методологию») запускают соответствующий процесс без уточняющих вопросов. Каскадные изменения — через ADR с обязательной секцией pre-flight checks (шаблон wiki/templates/template-adr.md).

Подтверди в 3–5 строках: какая текущая конфигурация системы, какие открытые нити есть в свежем handoff, готов ли к работе. Затем жди задачу.
```

**Шаг 4.** Дождись подтверждения от Claude (3–5 строк с резюме контекста). Если резюме не отражает актуального состояния — попроси перечитать handoff-файл и повторить.

**Шаг 5.** Ставь задачу.

## Verification

Признаки успешного handoff'а:
- В первом ответе Claude упоминает текущую структуру vault'а, правильный номер последнего ADR, открытые задачи из handoff-файла.
- Claude не задаёт вопросов про базовые предпочтения (язык, формат журнала, права на правки), которые уже в `AGENTS.md` и auto-memory.
- Первая содержательная задача отрабатывается без переспроса «где у нас лежит X» — Claude находит через `index.md` и handoff.

## Rollback

Откат не применим: handoff — пассивная передача контекста через файлы, не изменение состояния. Если новая сессия неправильно подхватила контекст — попроси конкретно перечитать handoff-файл и `methodology-overview`, или начни новый чат с уточнённым промптом.

## What NOT to do

- **Не вставляй handoff-промпт после первой задачи.** Сначала подгрузка контекста, потом работа. Иначе Claude отвечает «из головы», игнорируя зафиксированный стандарт.
- **Не пересказывай Claude историю проекта в свободной форме.** Всё уже в handoff-файле, journal'е, ADR. Пересказ дублирует данные и создаёт риск рассогласования.
- **Не пиши handoff-файл от руки.** Это работа Claude в конце предыдущей сессии (триггер «закрой сессию» / «зафиксируй сделанное» из AGENTS.md). Если файл не создан перед handoff'ом — попроси Claude его создать в текущей сессии до её закрытия.
- **Не меняй конвенции (имена файлов, структуру разделов) в handoff-промпте.** Если хочешь изменить методологию — это каскадное изменение, через ADR. Handoff — это передача состояния, не реформа.
