# Runbook: начало новой сессии

Что Claude делает автоматически при старте новой сессии в корне рабочей папки (или подпапке). Этот runbook — для пользователя и для контроля поведения агента: понимать, что должно произойти без явных инструкций.

## Prerequisites

- `<root>/AGENTS.md` существует как symlink на `obsidian-aura/AGENTS.md` (создаётся install-скриптом пакета).
- Auto-memory в служебной директории профиля Claude Code существует и читается автоматически.
- `claude` запущен в одной из: корне рабочей папки, `obsidian-aura/`, опциональной папке проекта, или их подпапках.

## Procedure (что я делаю автоматически)

1. **AGENTS.md загружается в системный промпт** — через symlink или прямо. В контексте сразу доступны разделы: «Память Claude», «Каскадные изменения», «Автономность и триггеры», «Работа над конкретным проектом», «Шаблоны страниц», «Корневой symlink».

2. **Auto-memory подгружается** — индексный файл и все memory-файлы (user-предпочтения, feedback-правила, project-контекст, reference-указатели).

3. **Если у проекта-владельца vault'а есть свой репо с собственным AGENTS.md** (например, `<root>/<project>/AGENTS.md`) — он дополнительно подгружается Claude Code, когда сессия запущена из этой папки. В нём обычно живёт project-specific reading map и порядок обязательного чтения briefing/spec-файлов.

4. **Перед первым содержательным ответом по проекту** — читаю последние одну-две записи в `journal/` для восстановления контекста «что делали, к чему пришли, что открыто».

5. **Перед ответом на содержательный вопрос** — смотрю `index.md`, определяю релевантные страницы wiki, читаю только их. Не сканирую wiki целиком.

## Verification

Признаки, что runbook отработал корректно:
- В первом ответе я опираюсь на стандарт без переспроса базовых вопросов (язык общения, права на действия, текущий проект, формат записей).
- При упоминании пользователем артефактов проекта (термины, имена файлов, инциденты) — узнаю их сразу через память.
- Стандартные триггеры («обработай», «сохрани», «закрой сессию», «зафиксируй решение») сразу запускают соответствующий процесс без уточняющих вопросов.

## What NOT to do

- **Не отвечать «из головы»** по содержательным темам, если в vault есть зафиксированный ответ.
- **Не предполагать, что vault пуст** — всегда сначала `index.md`.
- **Не задавать вопросы про предпочтения**, которые уже в `AGENTS.md` или auto-memory (язык, автономность, политика подтверждений и т.п.).
- **Не дублировать в auto-memory** содержание, которое есть в vault — auto-memory это указатели, не копия.
- **Не считать сессию «новой»** для пользователя — он работает с одной системой, переходящей между сессиями через память.

## Rollback

Откат не применим: это пассивный процесс загрузки контекста, не изменение состояния.
