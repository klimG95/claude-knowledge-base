## Pre-flight checks

_Заполняется для ADR, описывающих каскадные изменения или операции с файловой системой. Для обычных решений секция удаляется._

- [ ] Затронутые файлы перечислены полно (grep по vault на старые имена / пути / упоминания).
- [ ] Критическая операция (rename, mv, delete, переименование плагина) **протестирована dry-run** — без блокеров на уровне file watchers, lock'ов, активной редакторской сессии.
- [ ] Зависимости от внешних состояний выявлены (Obsidian запущен / закрыт, git-репо чист, активные процессы).
- [ ] Откат сформулирован и реалистичен (`git revert` или явная обратная команда).

Реальный урок прошлого, обоснующий этот раздел: попытка `rename`/`mv` папки vault при активной IDE-сессии с file watcher'ом возвращала `Access denied` со всех попыток (`Rename-Item`, `cmd move`, `.NET Directory.Move`). План пришлось переписывать посреди выполнения. Pre-flight check ловит такие блокировки до начала. Раздел — обязательная страховка для каскадов и FS-операций.
