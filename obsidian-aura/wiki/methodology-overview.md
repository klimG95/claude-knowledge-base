# Methodology — обзор системы

Сводная карта инфраструктуры, выстроенной в этой рабочей папке для ведения базы знаний и сопровождения проектов пользователя. Документ для пользователя — что есть, для чего, куда смотреть когда возникает потребность. Правила работы агента в этих рамках — в `AGENTS.md`.

## Структура рабочей папки

```
<root>/
├── AGENTS.md                ← symlink на obsidian-aura/AGENTS.md
├── obsidian-aura/           ← vault (база знаний + операционный центр)
│   ├── AGENTS.md            ← полная конституция агента (источник истины)
│   ├── index.md             ← оглавление wiki
│   ├── CHANGELOG.md         ← журнал изменений vault
│   ├── wiki/                ← обработанные знания
│   │   ├── templates/       ← шаблоны страниц (ADR, incident, runbook, weekly-review, component, ...)
│   │   ├── adr-NNN-*.md     ← архитектурные решения
│   │   ├── runbook-*.md     ← операционные процедуры
│   │   └── ...              ← страницы по темам
│   ├── journal/             ← дневник работы над проектами
│   └── raw/                 ← сырьё для обработки
└── <project>/               ← (опционально) код проекта рядом с vault'ом
```

Плюс auto-memory — короткие указатели и личный контекст в служебной директории профиля Claude Code.

## Три слоя памяти

| Слой | Где живёт | Что хранит |
|------|-----------|------------|
| Семантический | `obsidian-aura/wiki/` + `index.md` | Знания: концепции, факты, источники, связи |
| Процедурный | `obsidian-aura/AGENTS.md` (доступен и через `<root>/AGENTS.md`) | Правила работы агента |
| Эпизодический | Auto-memory | Контекст про пользователя, указатели в vault, история |

При расхождении приоритет за vault'ом для решений, за кодом — для фактов о поведении.

## Главные процессы

**Захват сырья.** Пользователь складывает материалы в `raw/`. Команда «обработай» — стандартный процесс обработки в wiki с двусторонними связями.

**Работа над конкретным проектом.** Связка MOC проекта в `wiki/` + журнал в `journal/` + код в соседней папке. Vault содержит контекст решений, код — поведение.

**Архитектурные решения.** Нетривиальное решение → ADR в `wiki/adr-NNN-*.md` по [[templates/template-adr]]. Каскадные изменения методологии — обязательно ADR с разделом Migration plan.

**Инциденты.** Раздел в incidents-log проекта по [[templates/template-incident]]. Отдельный файл только если инцидент становится ссылочным эталоном.

**Операционные процедуры.** `wiki/runbook-*.md` по [[templates/template-runbook]]. Например, [[runbook-session-start]].

**Закрытие сессии.** Финальный sweep — `index.md` + `journal/YYYY-MM-DD.md` + `CHANGELOG.md` + auto-memory + проверка ссылочной целостности. Триггер — «закрой сессию» или «зафиксируй сделанное».

## Точки входа

- **Я впервые открываю vault** → [[methodology-overview]] (эта страница), затем [[AGENTS]] (конституция агента).
- **Нужна история решений** → ADR в `wiki/` (`adr-NNN-*.md`).
- **Ищу runbook процедуры** → `wiki/runbook-*.md`.
- **Хочу понять, как устроен проект-владелец vault'а** → MOC проекта (создаётся при кастомизации vault'а под проект; см. AGENT-MANUAL.md §«Кастомизация под проект»).

```dataview
  status,
  tags

```
