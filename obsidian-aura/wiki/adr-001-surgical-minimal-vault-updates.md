# ADR-001: Surgical & minimal updates в vault'е

**Status:** accepted
**Date:** 2026-05-24
**Project:** methodology

## Context

Анализ репо [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills) (CLAUDE.md из 4 принципов Карпатого о типовых ошибках LLM в коде) обнаружил два пробела в нашей конституции vault'а ([[AGENTS]]):

1. **Нет защиты от over-structuring.** AGENTS.md говорит «vault не дублирует код», но не запрещает спекулятивные секции на wiki-странице, новые шаблоны «на будущее», избыточные подзаголовки без поддержки источника. На практике это приводит к разрастанию страниц с разделами, в которых одна строка «TBD».
2. **Нет правила про хирургичность правок.** При обновлении страницы по конкретному инциденту легко начать «причёсывать» соседние секции — переформулировать, разбивать абзацы, менять wikilinks. Это создаёт шум в diff'е, мешает ревью CHANGELOG, и иногда непреднамеренно меняет смысл соседних формулировок.

Дополнительно — PHASE 3 в [[runbook-vault-integration]] перечисляет действия capture-фазы («обновить index.md»), но не задаёт **верифицируемых критериев** их выполнения (нет битых ссылок, новые страницы реально присутствуют в index.md, etc.). Полная проверка живёт только в триггере «ревизия», который запускается редко.

## Considered options

1. **Status quo** — оставить как есть, опираться на здравый смысл при правках. Плюс: ничего не меняем. Минус: пробелы реальные, симптомы уже наблюдались (раздутые секции в auragrid-* страницах, drive-by-правки соседних абзацев в одном коммите).

2. **Полная интеграция 4 принципов Карпатого** — добавить Think Before / Simplicity First / Surgical Changes / Goal-Driven Execution как отдельные разделы AGENTS.md. Плюс: системность. Минус: «Think Before Coding» в духе «спроси прежде чем делать» противоречит установке [[feedback_technical_autonomy]] (пользователь не программист, технические выборы — на агенте); «Goal-Driven Execution» уже частично в трёх фазах runbook.

3. **Точечная интеграция двух применимых принципов** — добавить в AGENTS.md разделы «Минимализм правок» (Surgical) и «Минимализм структуры» (Simplicity); расширить PHASE 3 runbook'а явными verify-критериями. «Think Before» и «Goal-Driven» — не добавлять; ограниченно применяю их в текущей практике (выбранная интерпретация одной строкой в начале ответа, capture-чек-лист как сам verify-loop).

4. **Создать отдельный runbook `runbook-surgical-edits.md` без правки AGENTS.md** — Плюс: AGENTS.md не растёт. Минус: AGENTS.md — конституция, базовые принципы правок должны быть в ней; runbook — это операционная процедура, а не общий принцип.

## Decision

**Выбран Option 3 — точечная интеграция.** Самый сильный аргумент: оба добавляемых принципа закрывают наблюдаемые пробелы и не вступают в конфликт с действующими feedback-правилами автономии. Опция 2 ломала бы автономию агента ради общности.

Конкретно:
- В [[AGENTS]] добавляются два раздела перед «Принципы, которые объединяют всё вышесказанное»: «Минимализм правок» и «Минимализм структуры».
- В [[runbook-vault-integration]] PHASE 3 дополняется блоком «Verify» с явными проверяемыми критериями.

## Consequences

**Положительные.** Снижение шума в diff'ах vault'а. Меньше спекулятивных секций на wiki-страницах. Capture-фаза становится самодостаточной (не зависит от триггера «ревизия» для базовых проверок). Принципы Карпатого встроены в местах, где они применимы, а не как ритуал.

**Цена.** Два дополнительных раздела в AGENTS.md (≈30 строк), один блок в runbook (≈15 строк). Растёт объём конституции — приходится при чтении проходить чуть больше материала.

**Follow-ups.** Не возникает обязанности ретроспективно «приводить в порядок» существующие страницы (по тем же принципам — это было бы non-surgical). Старые страницы остаются как есть; принципы применяются к будущим правкам. При следующей сессии-«ревизии» можно опционально пройтись по auragrid-* страницам и применить Simplicity-правила.

## Migration plan

**Затронутые файлы (4 правки + 2 создания):**

1. `obsidian-aura/AGENTS.md` — добавить два раздела перед «Принципы, которые объединяют всё вышесказанное».
2. `obsidian-aura/wiki/runbook-vault-integration.md` — расширить PHASE 3 блоком «Verify».
3. `obsidian-aura/index.md` — добавить ADR-001 в новый подраздел «ADR» (раздела ADR ещё нет, создаётся).
4. `obsidian-aura/CHANGELOG.md` — запись о сессии со ссылкой на этот ADR.
5. `obsidian-aura/wiki/adr-001-surgical-minimal-vault-updates.md` — этот файл (создаётся).
6. `obsidian-aura/journal/2026-05-24.md` — детальная запись сессии (создаётся).

**Характер правок:** добавления, не удаления и не переформулировки существующих разделов (сам принцип «Surgical» применяется к самому ADR).

**Атомарность:** одна сессия — 6 файлов, существенно меньше порога 30 из AGENTS.md. Migration window не нужен.

**Проверки после миграции (verify-критерии этой миграции):**
- `grep` по vault на `[[adr-001-` → ссылка из index.md и CHANGELOG.md присутствует.
- AGENTS.md содержит секции `## Минимализм правок` и `## Минимализм структуры`.
- runbook-vault-integration.md содержит подраздел `### Verify` внутри PHASE 3.
- Битых `[[ссылок]]` не появилось — grep на новые имена даёт совпадения только в созданных/изменённых файлах.

**Откат.** Vault версионируется git'ом. При обнаружении проблем — `git revert` коммита миграции.
